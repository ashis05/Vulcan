# VULCAN — Screen Specification · Phased Build Plan

**Intent:** Build the VULCAN Screen Specification as a working, dark-only mobile app prototype — tokens → primitives → components → 30 screens (S1–S30) → global states — following the build order in `context/input-DESIGN.md` §10. Every value is a token; no one-off colors or spacing.

## Authority & token reconciliation

`context/input-DESIGN.md` (§1–§11) is the source of truth for this build. Two auto-extracted files disagree with it, and the input document wins:

| Conflict | Auto-extracted file | Truth (input doc) | Action |
| --- | --- | --- | --- |
| Palette roles | `DESIGN.md` labels `#f5f2ec` as *background*, `#0b0b0d` as *foreground* | §3: dark canvas is `bg.base #0B0B0D`; text.primary is `#F5F2EC` | Bind §3 verbatim |
| Display face | `DESIGN.md` / `system/*` say Inter for everything | §4: **Space Grotesk** for display & numerals, Inter for body | Use both faces in `screens/` |
| Token set | `system/tokens.dark.json` / `variables.dark.css` = generic dark algorithm (primary `#dc7726`, bg `#1d1d1d`) | §3: full bespoke set (ember scale, glow, flame gradient, radius/size scale) | Do **not** reuse `system/` tokens; create a dedicated `screens/shared/tokens.css` from §3 |

Keep `system/kit.dark.html` as reference tooling only. Reuse the Spark mark as needed from `logos/logo.png` (mechanical, not regenerated by hand).

## Key decisions

- **Dark theme only** (per input doc). No light theme anywhere in the screens.
- **Surface:** web. Mobile-first responsive, one-thumb reach, 390px comfort width, degrades to full-width on desktop.
- **One screen per file** under `screens/`; `index.html` (root) = launcher/overview linking all 30 + the shell.
- **Navigable prototype** — bottom tab bar + route transitions are live; buttons/CTAs wire to their target screens (per project metadata: real product UI with working interactions, not static mockups).
- **Numerals:** Space Grotesk + `tabular-nums` wherever a value changes (weights, kcal, timers).
- **Presentation:** full-bleed mobile layout in the preview pane — no phone frame.
- **Scope & cadence (locked):** hero path first, milestones only. P1–P5 (system + shell) → *review* → P6–P8 (auth/onboarding → Today → Train core) → *review* → P9–P13 (remaining screens) → P14 (global states & QA) → *review*.
- Gesture affordances (swipe on SetRow, drag on photo compare) are click/button equivalents in browser reality.

## File architecture

```
screens/
  shared/
    tokens.css        ← §3 tokens, :root dark (the single source: every color/spacing/radius referenced as var())
    base.css          ← typography scale, layout, tabular-nums, focus rules
    components.css    ← all primitives + data + workout components
    shell.css / shell.js   ← bottom tab bar, route nav, toast, bottom sheet
    mock-data.js      ← fixture users, routines, sets, meals, weights, AI copy
  s01-splash.html … s30-privacy-data.html   (one per screen, see map below)
index.html            ← launcher/overview + route index
```

Every shared asset is imported (`<link>`/`<script>`) by each screen — one edit refreshes the whole spec.

## Global acceptance checks (every screen)

- Every color, spacing, radius, shadow is a `var()` from `tokens.css` — zero raw literals.
- Touch targets ≥44px (SetRow 48px); contrast AA on dark; focus visible (ember ring).
- Display numerals Space Grotesk + tabular-nums; ≤2 weights per screen.
- One glow at a time — the accent glows, static chrome stays flat.
- Ignite semantics: completion/streak/PR/heat = ember treatment; never decorative.
- AI surfaces carry an "AI estimate / guidance" caption + ConfidenceChip where specified.
- States present where the spec names them: loading skeleton · empty ("Nothing forged yet…") · error (inline caption or toast, never full-block) · offline banner on Today/S10.
- Voice: terse coach, no exclamation marks except PR celebrations.
- `data-od-id` on regions, headings, CTAs, repeated cards.

## Decisions (locked by user)
